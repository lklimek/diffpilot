acme/node-client #482: retry with backoff on timeout

LLM analysis unless marked otherwise.

What the change gives: the wallet no longer shows “offline” after one late reply; a call is tried up to 3 times and a dead peer is noticed in 5 s instead of 30 s. Why it is needed: issue #470, the wallet UI hung for 30 s on unreachable peers.

Highest-rated question: Can broadcast_tx be sent twice when the reply arrives late? → HIGH

Send an RPC request with retry

HIGH flowOpen group 1 in the workspace

LLM analysis unless marked otherwise.

What it gives: a call survives a late or lost reply by trying up to 3 times.

The flow starts when wallet::send_payment or mempool::broadcast_tx calls RpcClient::send. Step 2 builds the request and sends it once (build_request() is unchanged text moved out of send). Step 3 branches on the result: success returns, other errors return as before, a timeout goes to step 5.

Step 5 asks the new RetryPolicy::should_retry; if yes, step 6 waits backoff(attempt) and the loop returns to step 2; if no, step 7 returns the new Exhausted error. Group 4 removes send_once(), the only way to send without retry.

pub async fn send(&self, req: Request) -> Result<Response, RpcError> {
let policy = &self.retry;
let mut attempt: u32 = 0;
loop {
attempt += 1;
let http = self.build_request(&req)?;
let timeout = self.config.timeout;
match self.transport.execute(http, timeout).await {
Ok(resp) => return Ok(resp),
Err(RpcError::Timeout) if policy.should_retry(attempt) => {
let delay = policy.backoff(attempt);
tracing::warn!(attempt, ?delay, method = %req.method, "rpc timeout; retrying");
tokio::time::sleep(delay).await;
}
Err(RpcError::Timeout) => {
return Err(RpcError::Exhausted { attempts: attempt });
}
Err(e) => return Err(e),

Default timeout 30 s → 5 s

MEDIUM flowOpen group 2 in the workspace

LLM analysis unless marked otherwise.

What it gives: a dead peer is detected in 5 s instead of 30 s.

RpcConfig::default() sets the per-attempt timeout. sync::fetch_headers (unchanged, outside the diff) relied on the long default and its own comment says slow peers need 10–20 s.

New error variant RpcError::Exhausted

MEDIUM flowOpen group 3 in the workspace

LLM analysis unless marked otherwise.

What it gives: callers can tell “retried and failed” from a single timeout.

Two places outside the diff match on the result of send() with a wildcard arm (same pattern × 2), so Exhausted falls into the generic branch there.

#[non_exhaustive]
#[derive(Debug, thiserror::Error)]
pub enum RpcError {
#[error("request timed out")]
Timeout,
#[error("gave up after {attempts} attempts")]
Exhausted { attempts: u32 },
#[error("transport failure: {0}")]
Transport(#[from] TransportError),
}
