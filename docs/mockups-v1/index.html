smart-review — mockups

Static HTML for user consultation. One example PR throughout: acme/node-client #482 “feat(rpc): retry with backoff on timeout” (Rust, 14 files, +612 −148). Screens follow ../design-brief.md §4. Most pages have a “mockup states” bar at the top.

  1. 01 Home — PR URL field, recent reviews; states: empty, error, loading, signed out.
  2. 02 Analysis progress — stages and groups filling in; states: usage-limit pause, failed chunk with retry.
  3. 03 Overview — summary, Needs attention, groups by importance, collapsed noise; states: stale, partial, loading, error.
  4. 04 Group workspace — the core: hover tooltip, click-to-pin inspector, old code, mark reviewed, ask, comment. Contains groups 1–6 (verified move, move with 2 differences, deleted site).
  5. 05 Tour — the same content as a linear sequence; next/previous, noise skipped by default.
  6. 06 Files — tree (Production / Tests / Docs / Generated) with risk dots; folded unchanged regions.
  7. 07 Re-review — delta since your review: new / changed / unchanged groups, earlier comments with status.
  8. 08 Pending review — draft comments drawer; push to GitHub as a pending review; states: error, pushed, empty.
  9. 09 Settings — Codex sign-in and usage, LLM language, GitHub App, per-repo rules.

Press ? on any page for keyboard shortcuts. Light/dark follows the system setting. No network requests are made.
