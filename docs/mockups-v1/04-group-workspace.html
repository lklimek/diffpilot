1. Retry policy in RpcClient::send HIGH behavioural LLM-claimed

Intent. Make RpcClient::send survive transient timeouts by retrying with exponential backoff.

Was

One attempt per call; a timeout is returned to the caller as RpcError::Timeout.

Is

Up to 3 attempts (200 ms base delay, doubling, capped at 4 s, jittered), then RpcError::Exhausted.

Consequences. Worst-case latency per call grows to about 3×timeout + delays; callers now see Exhausted instead of Timeout (group 3); every method is retried, including non-idempotent ones.

Retry also applies to non-idempotent calls

HIGHbug_suspectLLM-claimedconfidence 0.70

Behaviour

Was

One attempt; a timeout is returned as Timeout.

Is

Up to 3 attempts with 200 ms → 400 ms backoff, for any method.

Consequences

  • mempool::broadcast_tx may submit the same transaction twice if attempt 1 reached the node but the reply timed out.
  • Worst-case latency is now ~3 × 5 s + delays before the caller learns of a failure.
  • Callers receive Exhausted instead of Timeout (group 3).
