## 1. Principles

- **P1 One control per question.** When several controls answer one question the user asks ("what state is
  this in?", "which items do I see?"), they become one dropdown or popover. The trigger shows the current value
  or the most urgent one; the menu lists the rest with counts.
- **P2 Colour only for attention.** Neutral by default. Amber = needs you soon, red = broken or blocking, blue =
  something is running (only where the running thing is the row's subject, never as an alert). Colour never
  stands alone: every coloured mark also has a glyph and words (WCAG 1.4.1), contrast ≥ 4.5:1 for text, 3:1 for
  the glyph (1.4.11). At most one attention colour per row. A count of ordinary work (e.g. "Needs you · 5") is
  neutral; only genuinely urgent states (gate items, failures, a stopped LLM) are coloured.
- **P3 Facts and LLM stay apart.** Badges only for deterministic facts (stack position, release base, not
  live). LLM-derived states keep the existing "not final" language: dashed amber, `~`, an `LLM` tag.
  No percentages, no invented progress: counts, clock times and "since" only (the provider-reported Codex plan
  usage stays as today, labelled as reported by the plan).
- **P4 Fixed places.** Page state in the top bar; row actions in the row's right action column, rare ones in
  its `⋯` menu; filters in the list header; settings pages in the left navigation. The same thing looks and
  behaves the same on every screen (one Watch, one menu primitive, one judgement mark, one GitHub icon).
- **P5 Visible state.** Filters show as removable chips and live in the URL; nothing hides items silently.
  Anything folded (duplicates, status comments, excluded) keeps a count and one click to show it.
- **P6 Keyboard and screen readers.** Menus follow the WAI-ARIA menu button pattern (`aria-haspopup`,
  `aria-expanded`, arrow keys, Home/End, Esc returns focus to the trigger); single-choice menus use
  `menuitemradio`, toggles `menuitemcheckbox`. Panels with mixed content (user menu, status popover) are
  non-modal disclosures: Tab moves through them, Esc closes and returns focus. Live changes announce through the
  existing `role="status"` regions; targets ≥ 24 × 24 px (2.5.8).
- **P7 Phone stays usable.** Below 640 px: the Refresh split button becomes icon-only, chips scroll
  horizontally; the left navigation behaves as today's AppNav.
- **P8 GitHub links** always use the existing GitHub icon (`components/github/GithubMark.tsx`, `GithubIcon`),
  never `↗`. `↗` remains only for non-GitHub external links (MemCan TODOs).

## 7. Responsive and accessibility notes

- **U34**: < 640 px — split button icon-only with `aria-label`; crumb hidden; chips row `overflow-x: auto`;
  left navigation and its Settings sub-items as today's AppNav (U35).
- Filter buttons inside rows are real `<button>`s (today's tags are focusable spans with tooltips); their
  accessible name is "Filter by label CI failing". Chip body: `aria-pressed` = excluded.
- The judgement mark is a button only when outdated; otherwise a `<span>` with the tooltip, as today.
- The user menu panel is a non-modal disclosure; job count changes are not announced; an LLM failure is
  announced once through the shell's status region and shown by the U40 dot.
- U44's `×`: `<button aria-label="Hide">`; the banner is `role="status"` so new states are announced.
- GitHub icon links: the id's link keeps the accessible name "Open owner/repo#n on GitHub, new tab"
  (`GithubMark`'s sr-only text); duplicate title links are `aria-hidden` (U13).

## 8. Trust and wording check

- New fact badges (U9, U14, U15) are deterministic (installation list, GitHub base/stack, configured patterns).
- "outdated" states a fact (inputs changed after the judgement), not a quality verdict; the old text stays
  readable, tagged `LLM` with its date.
- No percentages added; U18 removes one. Meters in U31 show counts with their numbers.
- "Status comments" (U24) are listed, never dropped (silence is not safety).
